# 3.4.1 version display and cache repair

Production audit: all three HTML entrypoints, service worker, VERSION.txt, package.json, core runtime, cast loader, PWA client and all three character sheets matched deployed commit d6542e7fb9c95854b627432530e327c00a397169 byte for byte. This is not a deployment mismatch. The active SoCal badge said v3.4; VERSION.txt incorrectly said 2.5.3. No active HTML/runtime file contains 3.0.0. Archived documentation, fixtures, save keys and historical filenames are not release badges and remain unchanged.

The reported 3.0.0 display is consistent with an old installed release snapshot. The owner's browser storage was not inspected, so its exact cached version cannot be established. The worker deliberately serves cached navigations and ignores asset query strings to preserve a complete offline release. Changing HTML text or query strings alone therefore cannot replace an installed snapshot, and reusing the same cache name would write into the active release before approval.

The authoritative source is js/core/quest-release.js. QuestCore and the service worker read it directly; all three visible title badges are populated from it. VERSION.txt and package.json are checked mirrors; fallback HTML labels and titles are verified against it. Release version remains 3.4.1. A separate display-repair-1 cache revision gives this repair an isolated snapshot. Installation uses reload requests to avoid HTTP-cache reuse. Previous caches and localStorage remain intact. Navigations stay in the installed snapshot until the user accepts UPDATE READY. The existing client pauses and saves active gameplay before requesting worker activation, blocks activation if saving fails, and reloads only the requesting tab.

Regression coverage checks metadata and all three visible versions, simulates installed 3.0.0 cached HTML, verifies it remains unchanged while the repair waits, verifies save failure prevents activation, then accepts the update and verifies pause/save markers, untouched save storage, retained previous cache and offline version 3.4.1 in all three adventures. Existing full unit/browser suites also run. Production checks and final SHA are recorded with delivery. Physical phone testing and inspection of the owner's browser cache remain outside these automated checks.
